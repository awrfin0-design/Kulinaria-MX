# Languages (i18n)

## What ships
- `locales/es.default.json`: Spanish (default language of the theme).
- `locales/en.json`: English. Same keys, checked by the test suite.

All storefront text lives in these files and is output with `{{ 'section.key' | t }}`. JavaScript messages (countdown, compatibility, alerts) are injected by `layout/theme.liquid` into `window.KULINARIA.i18n` from the `js.*` keys (placeholders use `{name}`).

## Turning English on in Shopify
1. *Settings → Languages → Add language → English* and publish it (or enable it per Market).
2. The header and the full-screen menu show an **ES / EN** switcher automatically (`snippets/lang-switcher.liquid`, Shopify's `localization` form). With one language it hides itself.
3. Content typed in the theme editor (hero headline, tiers text, FAQ…), products, collections, pages and menus are *merchant content*. Translate them in **Translate & Adapt** (auto-translate + review). `scripts/render/content.en.json` contains reviewed English for all the sample content, which is the same text you can paste in.

## Things to know
- **Do not translate the `allergens`, `ingredients`, `diets`, `category` or `tier` metafield values.** Allergy blocking compares stored (Spanish) values; the theme shows friendly labels through `snippets/term.liquid` and the `allergen.*` / `ingredient.*` keys, falling back to the raw value when a key is missing. To add an ingredient label add `ingredient.<handle>` to both locale files.
- Filter chips (`category.*`, `diet.*`, `tier.*`) are translated by key; their `data-value` stays canonical.
- Admin-side labels in the theme editor are Spanish (merchant language).

## Add another language
Copy `locales/en.json` to `locales/fr.json` (for example), translate the values, publish the language in Shopify. No code changes.
